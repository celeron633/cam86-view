# 图像采集流程

## 1. 采集请求

UI 将参数整理为 `ExposureRequest`：

```cpp
struct ExposureRequest {
    bool bin2x2;
    bool roi;
    int roiCenterY;
    double seconds;
};
```

当前硬件协议始终采集完整宽度 3000，只在纵向选择行范围：

- 全画幅：2000 行；
- ROI：以主图选中位置为中心的 100 行；
- ROI 起始位置限制在 `[0, 1900]`；
- 协议以“两行为一组”，起始行和高度应保持偶数。

## 2. 单帧端到端时序

```text
UI GET IMG
  → CameraController::startCapture()
  → 工作线程 ICamera::capture()
  → 设置起始行 0x4B
  → 设置行数   0x5B
  → 设置 bin    0x8B
  → 设置曝光    0x6B
  → 曝光等待
  → purge A RX
  → 异步挂起 A bulk IN
  → B 发送读帧命令 0x1B
  → 等待 A payload 完成
  → decodeFramePayload()
  → Frame 放入完成队列
  → UI tick 取出 Frame
  → 暗场/显示处理/FITS
```

先挂起 A 通道读取，再发送 `0x1B` 非常重要。这样相机开始输出大帧时主机已经在排队读取，避免 FTDI 内部 FIFO 很快填满。新版使用 `std::async` 复刻旧版“读线程先启动、随后发读出命令”的顺序。

## 3. 短曝光与长曝光

### 曝光不大于 1 s

写入 `0x6B` 后直接进入读出流程。设置值为 `round(seconds × 1000)`。

### 曝光大于 1 s

相机只接收最大 1001 ms 的曝光设置，其余时间由主机计时：

1. `0x6B = 1001`；
2. `0x2B, 0`；
3. 等待 40 ms；
4. `0xCB, 0` 清帧；
5. 等待 180 ms；
6. `0x3B, 0`；
7. 主机等待约 `seconds - 1.2`；
8. 进入读出。

进度回调每约 20 ms 更新一次，并将曝光阶段限制在 95%，读出阶段显示约 96%，帧完成为 100%。

## 4. STOP 行为

`CameraController::stopCapture()` 设置原子取消标志。长曝光等待循环发现取消后提前结束，然后仍执行帧读出，行为接近旧版 `CameraStopExposure` 的“停止等待并读出当前帧”。

当前 `Cam86Camera::stopExposure()` 不会并行发送新的 USB 命令，因为采集线程可能正在使用 FT2232。限制包括：

- 不能立即取消已经进入的同步 bulk read；
- 读超时前窗口可能仍显示 Reading；
- STOP 不是硬件断电或 USB reset。

真机联调后若固件有专用 abort 命令，应在保持 I/O 串行化的前提下补充。

## 5. Payload 大小

令：

```text
rowPairs = sensorRows / 2
```

则当前预期有效 payload：

| 模式 | 每行对字节 | 全帧行对 | 全帧 payload |
| --- | ---: | ---: | ---: |
| unbinned | 12008 | 1000 | 12,008,000 bytes |
| 2×2 bin | 3008 | 1000 | 3,008,000 bytes |
| unbinned ROI 100 行 | 12008 | 50 | 600,400 bytes |
| bin ROI 100 行 | 3008 | 50 | 150,400 bytes |

这些数值不含 FTDI 每个 USB 包的两个状态字节；状态字节已经在传输层删除。

## 6. Unbinned 帧格式

每个行对是 6004 个 16 位 word，即 12008 字节：

```text
word 0..3      行对头部（当前跳过）
word 4..6003   1500 组 × 4 个 Bayer 样本
```

每组 4 word 映射到 2×2 传感器位置：

```text
source + 0 → (x,   y)
source + 1 → (x,   y+1)
source + 2 → (x+1, y+1)
source + 3 → (x+1, y)
```

word 按大端读取。映射后得到 3000×2000 的 GRBG 原始阵列：

```text
G R G R ...
B G B G ...
```

## 7. 2×2 bin 帧格式

每个行对是 1504 个 16 位 word，即 3008 字节：

```text
word 0..3      行对头部（当前推断）
word 4..1503   1500 个 bin 样本
```

每个样本复制到目标 2×2 区域，使 `Frame` 始终保持 3000×2000，简化 UI、暗场和 FITS 路径：

```text
sample → (x,y), (x+1,y), (x,y+1), (x+1,y+1)
```

旧 Delphi bin 分支使用了 `+7` word 偏移，但每行对总长只有 1504 word；处理最后像素时会越过行边界。新版依据总字数采用 4-word 头部。这是合理推断并有合成测试覆盖，但必须用真机 payload 确认。

## 8. Frame 数据结构

解码结果保存在：

```cpp
struct Frame {
    int width = 3000;
    int height = 2000;
    std::vector<std::uint16_t> pixels;
    double exposureSeconds;
    double sensorTemperature;
    time_point capturedAt;
};
```

内存大小约为 12 MB，不含 `std::vector` 元数据。Frame 保持 16 位原始值；Bayer、拉伸和纹理转换不会覆盖它。

## 9. CameraController 状态与交接

`CameraController` 负责：

- 阻止断开状态或忙状态重复开始采集；
- 启动 `std::jthread`；
- 通过 progress callback 更新原子状态和进度；
- 捕获异常并写入日志队列；
- 用 `optional<Frame>` 和互斥锁把结果交给 UI；
- 在断开和析构前取消并 join 工作线程。

UI 每帧调用 `takeFrame()`。取走后进度重置为 0，随后 `MainWindow::processCompletedFrame()` 执行图像后处理。

## 10. 连续采集

连续采集由 UI tick 调度，不在相机线程内部递归启动：

```text
条件 = continuous
    && connected
    && !busy
    && 未达到帧数上限
    && now >= nextCapture
```

完成一帧后：

- 帧号加 1；
- `nextCapture = now + delaySeconds`；
- 有限模式达到 `continuousFrames` 后停止；
- `Infinite capture` 开启时忽略帧数上限。

这种设计替代了旧 Delphi 的 Timer2/Timer3，并避免工作线程自行操作 UI。
