# 软件架构

## 1. 分层结构

```text
Application / MainWindow
          │
          ├── ControlPanel / ImagePanel / LogPanel / QFileDialog
          │
          ├── AppState ─────────────── ImageProcessor / FitsWriter
          │
          └── CameraController
                    │
                    ├── SimulatedCamera
                    │
                    └── Cam86Camera
                              │
                              ├── CAM86 protocol helpers
                              │
                              └── IUsbTransport
                                      │
                                      └── LibusbFtdiTransport
```

依赖方向始终从上层指向下层。USB 层不依赖 UI，图像处理也不依赖 OpenGL，因此协议和算法可以单独测试。

## 2. 模块职责

### app

- `Application`：初始化 QApplication，运行 Qt 事件循环，加载/保存配置。
- `AppState`：集中保存 UI 选择、连拍参数、相机控制器和图像处理器。

### ui

- `MainWindow`：组合三列布局，每帧拉取消息、温度和完成帧。
- `ControlPanel`：连接、曝光、连拍、ISO、暗场、FITS 和温控控件。
- `ImagePanel`：主图、50×50 放大图和直方图。
- `LogPanel`：显示控制器和处理流程日志。
- `QFileDialog`：跨平台 `.drk` 文件选择。
- `ImagePanel`：使用 QImage 和 QPainter 绘制 RGBA 图像。

### camera

- `ICamera`：真机和模拟相机共同接口。
- `CameraController`：后台采集线程、原子状态、进度、消息和完成帧交接。
- `Cam86Camera`：CAM86 初始化、命令发送、曝光和原始帧解码。
- `SimulatedCamera`：生成确定性的星点/渐变/噪声测试图。

### usb

- `IUsbTransport`：打开、关闭、控制请求和 bulk I/O 抽象。
- `LibusbFtdiTransport`：双接口 claim、端点传输、FTDI 控制请求。
- `FtdiProtocol`：波特率除数和 modem-status 字节剥离等纯算法。

### image

- `ImageProcessor`：暗场、Bayer、灰度、拉伸、预览、放大图、直方图和统计。
- `FitsWriter`：输出标准 2880 字节块对齐的 16 位 FITS。

## 3. 核心接口

`ICamera` 是相机后端的稳定边界，包含：

- `connect()` / `disconnect()`；
- Gain、Offset、温控设置；
- `capture(ExposureRequest, cancel, progress)`；
- `stopExposure()`。

`IUsbTransport` 是设备传输边界，包含：

- 设备枚举和双接口打开；
- FTDI reset、purge、latency、baud、bit mode；
- 指定通道的 bulk read/write。

新增其他相机或恢复 D2XX 后端时，应实现这些接口，而不是把平台代码写入 UI。

## 4. 线程模型

```text
UI 线程                           采集工作线程
   │                                    │
   ├─ startCapture(request) ───────────>│
   │                                    ├─ ICamera::capture()
   │<──── atomic state/progress ────────┤
   │                                    ├─ 完成 Frame
   │<──── mutex + optional<Frame> ──────┤
   ├─ processCompletedFrame()            │
   └─ Qt Widgets 更新                  │
```

- USB 和相机命令只在相机路径内执行；`Cam86Camera` 使用 `ioMutex_` 串行化 I/O。
- UI 不直接阻塞等待曝光，`CameraController` 使用 `std::jthread` 执行采集。
- `CameraState`、进度和取消标志使用原子变量。
- 完成帧、温度和日志队列通过互斥锁交接。
- Qt 控件和 QImage 只在 UI 线程更新。

## 5. 相机状态机

```text
Disconnected ── connect ──> Ready
Ready ── startCapture ──> Exposing ── readout ──> Reading ── frame ──> Ready
任意操作异常 ──> Error 或 Ready（取决于设备是否仍连接）
Ready/Error ── disconnect ──> Disconnected
```

UI 通过 `AppState::busy()` 把 `Exposing` 和 `Reading` 视为忙状态，避免在采集中重复发起曝光或读取温度。

## 6. 帧处理数据流

```text
USB payload
  → decodeFramePayload()
  → Frame{3000×2000 uint16}
  → ImageProcessor::accept()（暗场累加/扣除）
  → ImageProcessor::rebuild()（Bayer/灰度、拉伸、直方图）
  → RGBA preview/crop
  → ImagePanel::refresh()
  → Qt 显示
```

FITS 从 `ImageProcessor` 保存的 16 位 `Frame` 写出，不从 8 位预览纹理写出，因此显示拉伸不会破坏科学数据。

## 7. 扩展建议

- 新增相机：实现 `ICamera`，在 `CameraController::replaceCamera()` 中注册。
- 新增 USB 后端：实现 `IUsbTransport`，保持 CAM86 命令层不变。
- 新增去马赛克算法：在 `ImageProcessor` 中增加策略枚举，不要放入 `ImagePanel`。
- 新增文件格式：以 `Frame` 为输入创建独立 writer。
- 新增自动化测试：优先测试 protocol/image 纯函数，避免依赖窗口和真机。
