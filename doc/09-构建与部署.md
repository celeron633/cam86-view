# 构建与部署

## 1. 构建要求

- CMake 3.24 或更新版本；
- 支持 C++20 的编译器；
- Qt 6.2 或更新版本的 Widgets 模块；
- Windows 真机使用 FTDI D2XX 驱动和匹配架构的 DLL；Linux 真机需要 libusb 1.0。

Qt 必须与编译器及目标架构匹配。Windows 示例使用 Qt 6.8.3 的 msvc2022_64。

`CAM86_ENABLE_LIBUSB` 默认 ON，但找不到 libusb 时不会中止配置，Linux 下仅支持 Demo camera，Windows 下仍可使用 D2XX 真机后端。CMake 输出会显示：

```text
CAM86 libusb backend: ON
```

或：

```text
CAM86 libusb backend: OFF
```

## 2. CMake 目标

| Target | 类型 | 内容 |
| --- | --- | --- |
| `cam86_ui` | library | Qt Widgets 界面 |
| `cam86_core` | static library | camera、USB、image、config |
| `cam86-view` | executable | GUI 应用 |
| `cam86-tests` | executable | 核心自动测试，可选 |

配置选项：

| Option | 默认 | 说明 |
| --- | --- | --- |
| `CAM86_ENABLE_LIBUSB` | ON | 查找并启用真机后端 |
| `CAM86_BUILD_TESTS` | ON | 构建并注册 CTest |

## 3. Windows + Visual Studio + vcpkg

推荐使用 vcpkg manifest。仓库中的 `vcpkg.json` 固定 baseline 并声明 `libusb`。

```powershell
$vcpkgRoot = 'C:\path\to\vcpkg'

cmake -S . -B build/windows -A x64 `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64" `
  -DCMAKE_TOOLCHAIN_FILE="$vcpkgRoot\scripts\buildsystems\vcpkg.cmake" `
  -DVCPKG_TARGET_TRIPLET=x64-windows

cmake --build build/windows --config Release --parallel
ctest --test-dir build/windows -C Release --output-on-failure
```

输出通常位于：

```text
build/windows/Release/cam86-view.exe
build/windows/Release/libusb-1.0.dll
```

Windows 构建后自动执行 windeployqt，部署 Qt DLL 和平台插件。启用 libusb 时也需部署 `libusb-1.0.dll`。本机打包使用 `.github/scripts/package-windows.ps1 -Version 0.2.0`。

若 windeployqt 无法找到 Visual Studio 的运行库，目标机器需安装 x64 Visual C++ Redistributable。

### 不使用 libusb（Windows 仍支持 D2XX 真机）

不准备 vcpkg/libusb 时：

```powershell
cmake -S . -B build/demo -A x64 -DCAM86_ENABLE_LIBUSB=OFF `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build build/demo --config Release --parallel
ctest --test-dir build/demo -C Release --output-on-failure
```

## 4. Linux（Debian/Ubuntu）

安装依赖：

```bash
sudo apt update
sudo apt install build-essential cmake ninja-build libusb-1.0-0-dev \
  qt6-base-dev
```

使用 preset：

```bash
cmake --preset release
cmake --build --preset release
ctest --test-dir build/release --output-on-failure
./build/release/cam86-view
```

或传统方式：

```bash
cmake -S . -B build/linux -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/linux --parallel
ctest --test-dir build/linux --output-on-failure
./build/linux/cam86-view
```

Linux 使用 pkg-config 查找 `libusb-1.0`。

## 5. CMake Presets

仓库提供：

- configure preset `default`：`build/default`，Debug；
- configure preset `release`：`build/release`，Release；
- 对应 build preset；
- Debug test preset `default`。

多配置生成器会使用 preset 中的 `configuration` 字段；单配置生成器读取 `CMAKE_BUILD_TYPE`。

## 6. 自动测试

当前 `cam86-core-tests` 覆盖：

1. 每个 FTDI USB 包删除两个 modem-status 字节；
2. SPI 输出波形的高位编码；
3. Delphi `Word[]` 缓冲行为对应的响应采样位置；
4. unbinned 2×2 Bayer 样本排列；
5. bin 样本扩展到 2×2；
6. Demo camera 返回完整 3000×2000 Frame；
7. 图像处理生成正确尺寸的 RGBA 预览。

此外 `cam86-qt-ui-tests` 在隐藏窗口（Linux 使用 offscreen 平台）验证模拟相机连接、单帧采集、图像点击、ISO、FITS、有限连拍和停止行为，无需真实硬件。

运行：

```bash
ctest --test-dir <build-dir> --output-on-failure
```

Windows 多配置生成器需增加 `-C Debug` 或 `-C Release`。

## 7. 运行目录和数据文件

程序以当前工作目录为基准读写：

- `cam86.ini`；
- Output prefix 未包含目录时生成的 `.fit`；
- Save dark 未包含目录时生成的 `.drk`。

从 IDE、终端和资源管理器启动时工作目录可能不同。发布版如需固定数据目录，应后续增加用户数据目录设置，而不是依赖 exe 所在目录。

## 8. Windows 驱动部署

Windows 真机默认使用 D2XX，部署时检查：

1. 确认设备管理器中的 CAM86 FT2232H；
2. 保留旧客户端可用的 FTDI 驱动；
3. 确认设备枚举出 `CAM86A/CAM86B`；
4. 无需切换到 WinUSB；
5. 确认系统或 EXE 同目录有匹配客户端架构的 `ftd2xx.dll`；
6. 关闭旧 D2XX 软件，避免独占冲突。

## 9. Linux udev 部署

示例 `/etc/udev/rules.d/60-cam86.rules`：

```udev
SUBSYSTEM=="usb", ATTR{idVendor}=="0403", ATTR{idProduct}=="6010", MODE="0660", GROUP="plugdev"
```

加载：

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

重新插拔相机。生产规则建议增加 serial，并确认当前用户属于 `plugdev`。

## 10. 发布检查清单

- Release 配置构建成功；
- CTest 全部通过；
- Windows exe 为 GUI subsystem，无额外 CMD 窗口；
- Windows 包含匹配架构的 `libusb-1.0.dll`；
- 首次运行 Demo camera 可以连接和采集；
- 配置、FITS、暗场目录有写权限；
- 真机部署说明明确提示 D2XX/WinUSB 驱动切换风险；
- 记录构建使用的编译器、libusb 和 commit。
