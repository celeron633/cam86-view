# USB 与 FT2232 通信

## 1. 为什么不能把旧代码当普通串口

旧工程 `MyD2XX.pas` 直接调用 `FTD2XX.DLL`，`Cam86.pas` 同时打开 `CAM86A`、`CAM86B`。相机依赖 FT2232H 的双通道和 bit-bang 功能，并不是 UART 文本协议：

- 通道 A 连续接收大块 CCD 数据；
- 通道 B 输出 GPIO bit-bang 波形并采样返回位；
- D2XX 隐式处理 FTDI USB 包头、latency 和接口索引。

因此 libusb 可以替换 D2XX，但必须显式复现这些 FTDI 行为。

## 2. 设备识别

真机后端当前使用以下条件枚举：

| 字段 | 值 |
| --- | --- |
| Vendor ID | `0x0403` |
| Product ID | `0x6010` |
| Serial | 以 `CAM86` 开头 |

这对应 FTDI FT2232H 的常见默认 VID/PID。旧 Delphi 代码分别按 `CAM86A` 和 `CAM86B` 打开逻辑通道；libusb 后端打开一个 USB device handle，然后 claim interface 0 和 1。

如果实机 EEPROM 使用了自定义 PID 或不同 serial，需要修改 `Cam86Camera::connect()` 的枚举参数，最好后续改成配置项。

## 3. 接口和端点

| 逻辑通道 | USB interface | Bulk OUT | Bulk IN | 用途 |
| --- | ---: | ---: | ---: | --- |
| A | 0 | `0x02` | `0x81` | 图像帧读取，OUT 当前基本未使用 |
| B | 1 | `0x04` | `0x83` | bit-bang 控制波形和响应采样 |

后端通过 `libusb_get_max_packet_size()` 查询 A/B IN 端点包大小，不把 512 字节写死为唯一可能值。

## 4. 打开和关闭流程

打开：

1. `libusb_init()`；
2. 枚举所有 USB 设备；
3. 匹配 VID/PID 和 serial 前缀；
4. 打开 device handle；
5. Linux 下如内核驱动占用接口，执行 `libusb_detach_kernel_driver()`；
6. claim interface 0、1；
7. 查询两个 IN 端点的最大包大小。

关闭：

1. 按 B、A 顺序 release interface；
2. Linux 下重新 attach 之前卸载的内核驱动；
3. `libusb_close()`；
4. `libusb_exit()` 在传输对象析构时执行。

如果中途 claim 失败，异常清理路径也会释放已取得的接口。

## 5. FTDI vendor control request

FTDI 设置通过 endpoint 0 vendor request 发出。当前定义：

| 功能 | bRequest | wValue | wIndex |
| --- | ---: | --- | --- |
| Reset | `0` | `0` | 通道索引 |
| Purge RX | `0` | `1` | 通道索引 |
| Purge TX | `0` | `2` | 通道索引 |
| Set baud rate | `3` | divisor 低 16 位 | divisor 高位、high-speed 标记、通道 |
| Set latency | `9` | 毫秒数 | 通道索引 |
| Set bit mode | `11` | `mode << 8 | mask` | 通道索引 |

FTDI 通道索引不是 C++ 枚举值本身：A 使用 1，B 使用 2。

连接时 B 通道设置为：

```text
mask = 0xBF
mode = 0x04    // asynchronous bit-bang
baud = 20000
latency A/B = 1 ms
```

波特率编码由 `ftdi::encodeBaudRate()` 完成。FT2232H 使用 high-speed 标记 `0x0200`，并按 FTDI 的 1/8 分数除数表编码。

## 6. Bulk OUT

`write()` 会循环调用 `libusb_bulk_transfer()`，直到所有字节发送完成。单次分块上限为 1 MiB，控制波形本身通常只有 64 或 100 字节。

每次传输必须检查：

- libusb 返回值是否为 `LIBUSB_SUCCESS`；
- `transferred` 是否大于 0；
- 是否已经发送完整 span。

## 7. Bulk IN 与 FTDI 状态头

FTDI 每个 USB bulk IN 包的前两个字节是 modem/line status。D2XX 在交给应用前会自动删除，libusb 返回的则是原始包。例如最大包长为 8 的演示数据：

```text
USB:     S0 S1 D0 D1 D2 D3 D4 D5 | S0 S1 D6 D7 D8
payload:       D0 D1 D2 D3 D4 D5 |       D6 D7 D8
```

必须对每个 USB 包分别跳过两个字节，不能只删除整个 transfer 的前两个字节。实现位于 `ftdi::stripModemStatusBytes()`。

`read(channel, payloadBytes, timeout)` 会重复读 transfer、剥离状态头，直到收集到指定数量的有效负载。当前多余 payload 不做跨调用缓存，因为上层每次读之前都会按协议 purge 相应通道。

## 8. Purge 语义

新版接口使用清晰的 `purge(channel, rx, tx)` 参数。注意旧 `MyD2XX.pas` 的 `Purge_USB_Device_Out/In` 包装函数命名和实际 `FT_PURGE_RX/TX` 存在反向现象；重构时以实际方向为准，不沿用误导名称。

- 发送控制命令前：清空 B 的 RX/TX；
- 开始读帧前：清空 A 的 RX；
- 初始化后：清空 A/B 双向缓存。

## 9. 平台驱动

### Windows

libusb 不能通过 FTDI D2XX 内核驱动直接 claim 设备。需使用 Zadig 将 CAM86 对应接口切换为 WinUSB，且两个 FT2232H 接口都必须可访问。

风险：切换到 WinUSB 后旧 D2XX 软件不能继续使用该设备。恢复旧软件需重新安装 FTDI D2XX 驱动。不要误选电脑上的其他 FTDI 设备。

### Linux

程序会尝试临时 detach `ftdi_sio` 等内核驱动，但用户还需要 USB 访问权限。示例规则：

```udev
SUBSYSTEM=="usb", ATTR{idVendor}=="0403", ATTR{idProduct}=="6010", MODE="0660", GROUP="plugdev"
```

实际部署时建议再增加 serial 条件，避免放宽所有 `0403:6010` 设备。
