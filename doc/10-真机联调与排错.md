# 真机联调与排错

## 1. 验证边界

当前代码已经完成 Windows 构建、libusb 链接、自动测试和模拟采集，但开发环境没有 CAM86 实机。首次接入硬件时应将以下内容视为待验证假设：

- VID/PID 为 `0403:6010`；
- serial 以 `CAM86` 开头；
- interface/endpoint 与标准 FT2232H 布局一致；
- B 通道 `mask=0xBF, mode=0x04, baud=20000`；
- 命令字和温度编码与旧固件一致；
- unbin 行对 4-word 头部；
- bin 行对 4-word 头部。

## 2. 推荐联调顺序

不要一开始就进行长曝光和全帧反复读取。建议逐级验证。

### 阶段 A：USB 枚举

1. 使用系统工具确认 VID/PID、serial、configuration、interface 和 endpoint；
2. Windows 确认两个接口驱动都适配 libusb；
3. Linux 确认权限和 kernel driver detach；
4. 在 UI 选择 CAM86 / libusb，点击 CONNECT；
5. 只验证 claim、初始化和断开，不采图。

期望日志：

```text
Connected: CAM86 (libusb / FT2232H)
```

### 阶段 B：低风险控制命令

1. 读取温度；
2. 小范围修改目标温度但暂不开制冷；
3. 改变 Gain/Offset；
4. 用逻辑分析仪观察 B 通道波形；
5. 确认相机没有异常发热或电源状态变化。

温度返回应稳定在合理范围，异常值会被 `[-120,120] °C` 检查过滤。

### 阶段 C：短曝光 ROI

1. 关闭 bin；
2. 开启 ROI；
3. 选择画面中部；
4. 选择 0～100 ms 短曝光；
5. 单击 GET IMG；
6. 保存一份剥离 FTDI 状态头后的原始 payload 用于分析。

ROI unbin 期望有效 payload 为 600,400 字节。

### 阶段 D：全帧和 bin

1. unbin 全帧，检查 12,008,000 字节；
2. 检查 Bayer 排列、行起始和是否有固定错位；
3. 开启 bin，先 ROI 后全帧；
4. bin 全帧检查 3,008,000 字节；
5. 对比旧软件同条件输出。

### 阶段 E：长曝光和制冷

在短曝光稳定后再测试：

- 2 s、5 s、30 s 长曝光；
- STOP 的响应时间和读出行为；
- 制冷开关、目标温度和温度稳定性；
- 连拍、FITS 和暗场。

## 3. 常见错误与诊断

### `CAM86 FT2232H ... was not found`

按顺序检查：

1. 设备是否枚举；
2. VID/PID 是否不同；
3. serial 是否为空或不以 CAM86 开头；
4. Windows 驱动是否为 libusb 可用驱动；
5. 当前进程权限；
6. 设备是否被旧 D2XX 应用占用。

### claim interface 失败

- Windows：通常是接口驱动不对或另一个进程占用；
- Linux：通常是权限不足、内核驱动未成功 detach 或设备忙；
- 确认两个 interface 都存在，且端点不是被 EEPROM 配置成其他模式。

### 控制命令超时

检查：

- B OUT/IN 是否确为 `0x04/0x83`；
- bit-bang mode 和 mask；
- baud divisor；
- 每次命令前 purge 是否导致固件期望数据被误删；
- 100 ms 读写超时是否过短；
- FTDI 状态头是否按每个 USB 包剥离。

### 温度固定为 0 或跳变

- 捕获 B 通道 100 字节响应；
- 检查采样偏移 `18 + 2×i`；
- 核对 `0x40` 输入位；
- 比较旧 D2XX 返回 buffer；
- 验证固件温度偏移是否为 1280。

### 图像读取超时

- 确认先挂 A bulk IN，再发送 `0x1B`；
- 检查 A IN 为 `0x81`；
- 检查期望 payload 是否与 ROI/bin 一致；
- 增大 bulk read timeout；
- 检查 USB 线缆、Hub 和供电；
- 记录每次 transfer 的原始长度和剥头后的有效长度。

### 图像倾斜、错行或颜色异常

优先判断是不是帧格式而不是 Bayer 算法：

1. 查看每行对开头的 word 是否有固定 header；
2. 比较连续行对的边界；
3. 验证 word 大端/小端；
4. 用单色光或遮光图判断 GRBG 排列；
5. 比较旧软件保存的同一帧。

若画面每两行周期性错位，重点检查 `wordsPerPair` 和 `sourceBase`。

### bin 图像错位

这是当前最需要真机确认的部分。分别尝试并记录：

- 4-word 头部（当前实现）；
- 旧代码表面使用的 +7 偏移；
- 第一行对和后续行对是否结构不同；
- payload 中是否包含全帧头或尾。

不要只看画面“似乎正常”；应使用斜边、棋盘格或已知亮点位置验证所有行对。

## 4. 建议增加的诊断能力

真机联调分支建议加入可开关的诊断日志：

- USB bus/address、VID/PID、serial；
- interface descriptor 和 endpoint packet size；
- 每个 FTDI control request 的参数；
- 每次 bulk transfer 的原始/有效字节数；
- CAM86 command/parameter/response；
- 原始 payload 保存；
- 每个行对前 8～16 word 的十六进制摘要。

日志默认应关闭，避免全帧读取时产生大量输出和性能下降。不要记录无界的 12 MB payload 到普通 UI 日志。

## 5. 安全注意事项

- 切换 FTDI 驱动前确认设备身份并备份恢复方法；
- 首次制冷测试监控电流、散热和露点；
- 不要在曝光读出中强制关闭进程或拔线，除非设备已经失去响应；
- 长曝光前先验证 STOP；
- 修改 bit mask、AD9822 寄存器或电源相关命令前核对原理图；
- 不确定的命令不要通过穷举方式发送给真机。
